problem

Where the terminal stops helping

Five agents, one checkout, no way to see any of it.

  • Which one is working? You cannot tell working from idle from waiting an hour on you.
  • Whose files are these? Five agents collide in one checkout.
  • Who checked this? Nothing stands between what they wrote and your main branch.

kendle answers all three: a state in the sidebar, a worktree each, kendle gate before any push.

today

What it does today

Built, public, and checkable in an afternoon.

MIT, Python's standard library and a tmux config, so there is nothing to audit. Status: young — a month in one team's monorepo. Go and look.

A team per piece of work

One git worktree each, run by a manager you talk to and six sub-agents.

You touch it three times: the spec, plan, push. The roles go round until tests and review pass, then one commit through kendle gate.

Ask, review, logs, housekeeping

  • Ask Read-only questions on the latest base branch.
  • Review Someone else's changes side by side, read-only.
  • Logs The selected feature's services, live, with crash detection.
  • Housekeeping Idle services stopped, caches trimmed, resumable after a reboot.

Autopilot

File an issue, add a label, come back to a merged pull request — only your label, only accounts you listed. The team can never push or use gh.

What it promises, each learned the hard way

  • Keys never wait on data. 10 ms a keystroke, a hundred sessions open.
  • Idle means nobody worked on it. From the last real message, not file times.
  • Nothing is deleted on its own except caches whose worktree is gone.
  • Tests drive kendle as a user does. A throwaway repo, its own tmux socket.

install

Two commands, and nothing to audit

macOS or Linux, Python 3.9+, tmux 3.x, git, and Claude Code on your PATH. Nothing else.

git clone https://github.com/vuhah/kendle.git ~/kendle
export PATH="$HOME/kendle/bin:$PATH"

why now

Supervision, not generation, is the half nobody has solved.

Coding agents now run long enough, and independently enough, that one person keeps several going at once instead of watching one.

That moves the bottleneck: off writing the change, onto seeing across five of them and trusting one enough to let its work land. A better model does not solve that half.

where it's going

A console is the first rung, not the product

Everything below is a concept. Drawn, not shipped, and marked on its face. No dates, no roadmap.

A kendle session is four things: a worktree, a state, a gate, a log. Not one of them needs a terminal.

  1. 1 The hub

    One tmux server, one laptop, one person's sidebar: right while the work is yours, wrong the moment anyone else needs to see it. Move it somewhere a team opens and the same five states answer a bigger question: what is this team running, and what is waiting on a human? Nothing in the tool resists it.

  2. 2 A new engineer on the team

    It is Monday. At the top of that board is a feature nobody started on Friday: checkout double-charges on retry, picked up overnight, now on one question. It is the question a new hire asks — the two retry paths disagree about what counts as the same attempt; which is the rule? — and you answer it in a sentence. By the time you look again: a spec, a plan, one commit through the gate.

    What compounds is not the model, but what that answer taught it about this repository.

  3. 3 An assistant over the hub

    The console is keys today: a to ask, g to review, K to stop. Quick in your fingers, a wall before that. Saying it instead is nearer than it sounds: every one of those keys is already a command a script can drive.

  4. 4 Away from the desk

    Autopilot already runs without you, but the person it stops for has to be at a terminal: a run that blocks at midnight wastes the night. Answering from a bus stop is a small feature and a large change. It is the difference between agents that work while you sleep and agents that wait until you wake up.

  5. 5 Something people pay for

    The hub is the first rung that costs money to run and the first worth paying for. No price, no tier, no date: inventing one would be the same lie as inventing a user count. The tool is MIT and stays that way.

What would have to be true first. Three walls, and not one of them is a model problem. Shared state: one server two people can open, where today there is a socket on a laptop. Trust: who may start a session, and what an agent may run unwatched. Cost: unattended agents spend tokens every minute they run.

still open

What we do not know yet

Questions, not an order of work.

  • Where does the shared state live, and who runs it?
  • Who may start a session, and what may an agent run unwatched?
  • How does the cost of unattended agents stay predictable?
  • An open-source tool with something hosted beside it, or something else?
  • Which rung first, and what would tell us we picked wrong?
